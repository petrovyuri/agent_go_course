# Создание AI-агентов на Go с нуля: Eino, ReAct, RAG, MCP

Рабочий код к урокам курса. Агенты строятся на фреймворке
[Eino](https://github.com/cloudwego/eino) от CloudWeGo, модели запускаются локально через
[Ollama](https://ollama.com) — без облачных ключей и оплаты за токены.

## Что внутри

В репозитории две дорожки, которые идут параллельно:

1. **Уроки по модулям** (`module-01` … `module-13`) — каждая тема Eino на маленьком
   самостоятельном примере: сообщения, графы, инструменты, ReAct, состояние, RAG, MCP,
   трейсинг. Сюда заглядывают, чтобы разобрать одну конкретную возможность.
2. **Mini Code** (`minicode/`) — сквозной проект: мини-агент-кодер в духе Claude Code,
   который читает и правит файлы, ищет по проекту и работает в терминале. Он растёт от
   каркаса до готового инструмента по одной стадии за раз.

Каждый урок и каждая стадия — отдельный Go-модуль со своим `go.mod`, поэтому запускаются
независимо друг от друга.

## Mini Code — сквозной проект

Мини-агент-кодер на Eino + Ollama. От стадии к стадии он обрастает возможностями, при этом
ядро остаётся прежним — меняется только то, что добавили на текущем шаге.

| Стадия | Что добавляет |
|--------|---------------|
| `stage-01-skeleton` | каркас: терминал → граф → модель, с заготовкой под инструменты |
| `stage-02-file-tools` | чтение файлов: `read_file`, `list_dir`, `grep` (один раунд инструментов) |
| `stage-03-thinking` | настоящий ReAct-цикл через `react.Agent` — несколько шагов подряд |
| `stage-04-edit` | память сессии (`session.json`), правка кода (`write_file`, `edit_file`, `run_command`) и подтверждение опасных действий (HITL) |
| `stage-05-knowledge` | знание проекта через RAG (`search_code`) плюс внешние инструменты по MCP (`git_log`, `project_tree`) |
| `stage-06-final` | трейсинг в LangFuse, флаги командной строки, одноразовый режим для скриптов |
| `stage-07-ui` | терминальный интерфейс (TUI) поверх готового агента |

Финальная стадия запускается в трёх режимах:

```bash
go run .                       # REPL — диалог в консоли (по умолчанию)
go run . -q "что делает main.go?"   # одноразовый вопрос: ответил и вышел
go run . -ui                   # терминальный интерфейс
```

Флаги: `-model` (модель Ollama, по умолчанию `qwen3.5`), `-q` (одноразовый вопрос),
`-trace` (слать трейсы в LangFuse, если заданы ключи), `-ui` (TUI).

## Подготовка

```bash
# Go 1.26+  -> https://go.dev/dl/
go version

# Ollama    -> https://ollama.com/download
ollama --version

# модель с поддержкой инструментов (tool calling)
ollama pull qwen3.5

# модель эмбеддингов для RAG (модуль 11 и Mini Code)
ollama pull nomic-embed-text
```

Отдельные уроки используют другие модели (`llama3.1`, `qwen2.5-coder:1.5b`) — об этом сказано
в комментарии в начале их `main.go`. Ollama по умолчанию слушает `localhost:11434`.

## Запуск урока

Перейдите в папку нужного урока и запустите:

```bash
cd module-02-eino-core/lesson-05-prompt-template
go mod tidy   # один раз: подтянет зависимости
go run .
```

Урок 1.4 (проверка окружения) зависимостей не требует — там достаточно `go run .`.

## Трейсинг в LangFuse

Урок 13.3 и Mini Code умеют слать трейсы запусков в LangFuse. Нужны три переменные окружения:

```
LANGFUSE_BASE_URL
LANGFUSE_PUBLIC_KEY
LANGFUSE_SECRET_KEY
```

Без них код работает как обычно — трейсинг просто выключается.
